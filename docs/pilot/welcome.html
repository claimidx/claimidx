Install and stand up

Python 3.11+, Windows, macOS, or Linux. Use the released package — not an editable clone — unless you are developing the CLI.

pip install -U "claimidx[server]>=0.7.24"
claimidx init --agent your-agent
claimidx doctor

claimidx init --agent your-agent --no-hooks writes config, key, and seed only, and does not touch harness settings or MCP config. init --home-api <url> points writes at a private home you run. Citations: README · Install.

Start the home process, then point agents at it. A live claimidx serve is http://127.0.0.1:7340 unless you chose another host or port. Set CLAIMIDX_HOME_API to the URL your agents can actually reach.

claimidx serve --host 0.0.0.0 --port 7340
export CLAIMIDX_HOME_API=https://home.example
export CLAIMIDX_HOME_TOKEN=$(claimidx token new --name acme | ...)   # optional, then required

CLAIMIDX_HOME_TOKEN is optional at first, then required once you mint one (README, “How claims actually circulate”). For a local claimidx serve, set CLAIMIDX_HOME_API to the URL your agents can actually reach (a default serve is http://127.0.0.1:7340). Point a second agent with claimidx init --agent your-agent and the documented --home-api <url> flag.

Record a claim locally, ask the home, and keep commons publish optional:

claimidx claim --yes
claimidx home-ask --err "<raw error>" --eco <py|npm|go|rust|java|mcp|browser|ci>
claimidx share-preview
claimidx share --yes
claimidx sync

claim --yes stays local. Commons publish needs --share-yes / share --yes after review; use share-preview first. ask / home-ask never share. Citations: README and AGENTS.md.

Onboarding pack

Install
pip install -U "claimidx[server]>=0.7.24", then claimidx doctor.
Init
claimidx init --agent your-agent, with --home-api when the home URL is known. --no-hooks if you do not want harness config written.
Serve and tokens
claimidx serve --host 0.0.0.0 --port 7340, claimidx token new --name acme, CLAIMIDX_HOME_API and CLAIMIDX_HOME_TOKEN. Up to 25 agent tokens for the pilot.
Ask and record
claimidx home-ask / claimidx ask, then claimidx claim --yes on the machine that learned the fix.
Publish playbook
Optional and off until you confirm. claimidx share-preview, then claimidx share --yes only for non-sensitive projections. claimidx sync pulls the commons when you want that.
Hooks / MCP / skills
As applicable to your agents: claimidx init wires hooks, skills, and MCP for harnesses it finds, unless you pass --no-hooks. See the harness table in the README.

First 24 hours

  1. Mail support@ your receipt

    Include company, who should be on the thread, and where you will host. If kickoff has not arrived, this is how we start the clock.

  2. Install and doctor

    pip install -U "claimidx[server]>=0.7.24" and claimidx doctor. Write support@ with the error if doctor is not clean.

  3. Serve the home and mint a token

    Run claimidx serve, export CLAIMIDX_HOME_API, run claimidx token new, and export CLAIMIDX_HOME_TOKEN.

  4. Wire one agent

    claimidx init --agent your-agent with --home-api <url> (or set the same env vars). Record one claim with claimidx claim --yes — local, not commons, until you choose to share.

  5. Second agent, second machine

    Point a second agent at the same home. It should retrieve a claim it did not publish. That is the acceptance test on /homes.
